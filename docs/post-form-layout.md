# Post form — layout, step by step

Source: the captain's mock (three screenshots, top → bottom) and the follow-up
instruction "brand one row … (make one row)". **Every field is a full-width row
of its own**, top to bottom; the only rows that carry more than one control are
the paired toggle groups (Condition, Transmission, Tax Type). Section headings
are bold.

Since 2026-09-15 the form is **shared and schema-gated**: every block below
renders only if its key is in that subcategory's own backend `field_schema`, so
a row listed here can be absent on a subcategory that doesn't declare it (a
bicycle has no Brand/Model/Year/Engine Type/Body Type/Transmission/Tax Type/
Color). `\*` marks a field that is required — starred _and_ enforced at submit.

The form lives in `apps/web/components/post/ListingPostForm.tsx`; the Photos block
is `apps/web/components/post/ImageUpload.tsx`. **Every picker row (Brand, Model,
Year, Engine Type, Body Type, Color, Location) is the same `SearchPicker`**: a
full-width trigger that opens a rounded white Search field over a scrolling
list, 48px rows, light-grey highlight — no native `<select>` remains. Only the
two-button rows (Condition, Transmission, Tax Type) are not pickers.

## Deliberate deviations from the mock

- The mock shows a generic listing (bicycle), so it has no car fields. The cars
  form keeps **Brand, Model, Year, Engine Type, Body Type, Transmission, Tax
  Type and Colors** — each as its own full-width row, placed right after the
  category box, before Condition.
- `Location` posts the picked **province name** into the existing `location`
  string, so the create-listing contract is unchanged.
- **Condition's slot is per-subcategory (2026-09-21).** The rows above describe
  the cars order, where Body Type (11) comes before Condition (14). **Lorries,
  Vans & Tractors is the one exception**: it renders Condition → Body Type →
  Price, matching its mock and its `field_schema` order. The two relative orders
  contradict each other, so the shared component keeps a small explicit list
  (`CONDITION_BEFORE_BODY_TYPE` in `ListingPostForm.tsx`) rather than one global
  order; the exception only bites when the subcategory also declares `bodyType`.
- **Required-ness lives in the form, not the backend** (as of 2026-09-15). The
  `*` and the submit-time check are hardcoded per block, so Tax Type, Condition
  and Color are required on _every_ subcategory that declares them — Cars For
  Sale included. The DB `field_schema.required` flag is NOT consumed and does
  not currently agree with this layout: the seed marks everything except `title`
  and `price` as `required: false`, including year/taxType/color/condition/
  description/location/address/contactName/contactPhones, all of which the
  design stars. Fixing that means editing `categories.seed.ts` and re-seeding,
  then driving the stars from the schema — worth doing before the required set
  is allowed to differ per subcategory.
