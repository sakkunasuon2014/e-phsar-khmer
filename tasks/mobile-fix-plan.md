# Mobile Responsiveness Fix Plan — apps/web

**Date:** 2026-10-26
**Status:** Planning only — no application source was modified to produce this plan. Every finding below was re-verified by reading the actual files (not just the audit's prose) on 2026-10-26.
**Inputs:** `tasks/mobile-audit.md` (static pass §0–8, measured pass §9), `tasks/mobile-audit-visual.json` (raw measurement rows), `tasks/mobile-audit-shots/*.png`, live preview `http://localhost:3011` (backend `:8080`).

---

## 1. Summary

**Goal:** Eliminate page-level horizontal overflow on every public route at 320/360/390/768px, and bring primary touch targets up to the 44px guideline — without new dependencies, a `tailwind.config` file, or touching WIP/dirty files.

**Non-goals:**

- Any authenticated/admin surface beyond what `/en/login`, `/en/me` (redirect), `/en/chats` (login-gated shell) already show — those stay static-only per the audit's own scope limits.
- Dead-code removal (MR-007's five orphaned headers — see §2, the audit undercounted this by one file — are flagged, not deleted).
- `chat/*`, `lib/e2e/*`, `actions/e2e-backup.ts`, `messages/*.json` — all dirty/WIP, untouched.
- Locale stress testing (km/zh string lengths) beyond what's already visible in the shell overflow (the shell overflows identically regardless of locale, since the cause is layout, not copy length).
- New UI abstractions beyond what's needed to fix the four confirmed structural findings.

## 3. Workstreams

### W1 — Global shell: responsive nav + search + account block

- **Goal:** Make `NavBar`/`SearchBar`/`SocialBar` fit at 320–1023px with no horizontal overflow, while keeping the current desktop layout pixel-equivalent at ≥1024px.
- **Findings addressed:** MR-001, MR-006, MR-005 (nav-icon slice only).
- **Allowed files (exclusive to W1):**
  - `apps/web/components/web/NavBar.tsx`
  - `apps/web/components/web/SearchBar.tsx`
  - `apps/web/components/web/SocialBar.tsx`
  - `apps/web/components/web/MobileNavSheet.tsx` _(new file, created by W1 only)_
- **Implementation approach:**
  1. **Breakpoint choice — deliberately `lg:` (1024px), not `md:` (768px).** The measured data shows the current desktop row's own unavoidable minimum is 785px — _already wider than the `md:` cutover point (768px)_. Collapsing at `md:` would leave the desktop row showing, and 17px too wide, at exactly the 768px viewport the audit's own test matrix checks. Collapsing at `lg:` (`--breakpoint-lg: 64rem` = 1024px, already Tailwind's default and already used elsewhere in the repo, e.g. the search page's `lg:hidden` sidebar fallback) guarantees every acceptance viewport (320/360/390/768) gets the compact nav, and the full desktop row only ever renders where there's headroom (≥1024px).
  2. **`NavBar.tsx`:** keep the existing `<div className="flex items-center justify-between gap-4">` row, but split its three children into `hidden lg:flex`/`hidden lg:block` desktop-only wrappers (logo+locale+theme block; the `<Suspense>`-wrapped `SearchBar`; the login/register/sell-or-`SocialBar` block), and add one new `flex lg:hidden items-center justify-between w-full` row rendered only below `lg:` containing: the existing logo `<Link>` (reused as-is) and a new `<MobileNavSheet user={user} />`.
  3. **`MobileNavSheet.tsx` (new):** a client component taking the same `user: User | null` prop `NavBar` already has. Renders a single icon-only trigger button (`lucide-react`'s `Menu` icon — already a dependency, used elsewhere in this same file tree) that opens a shadcn `Sheet` (`components/ui/sheet.tsx` — **already in the repo**, confirmed via `components/ui/sidebar.tsx`'s own use of it; this is a new _use_ of an existing primitive, not a new dependency or new abstraction). `SheetContent` (side `"right"`, default width is already responsive per the primitive) stacks, top to bottom: the existing `<Suspense><SearchBar/></Suspense>` (reused unmodified — fixing MR-006 inside `SearchBar.tsx` benefits both the sheet and, if ever needed, the desktop row), a row with the existing `LocalSelector`/`ThemeSwitcher` (reused unmodified, no edits needed to either file), a `<Separator>` (already in `components/ui/`), and then either the three existing Login/Register/Sell links (duplicated verbatim from `NavBar.tsx`'s own logged-out branch — ~12 lines of plain JSX, not worth extracting for a second use this small) or the existing `<SocialBar user={user} />` component reused wholesale (its `DropdownMenu`-based bell/message/avatar row works at any width and its items are plain `onClick` links, so they're touch-operable without modification).
  4. **`SearchBar.tsx:130`:** change the scope-trigger button's `w-[170px]` to `w-[120px] sm:w-[170px]`, and its label's `max-w-[115px]` (line 132) to `max-w-[70px] sm:max-w-[115px]` so the truncated text shrinks in step. This is a correctness fix independent of where the bar renders (desktop row or inside the new sheet) — at the narrowest supported width (320px, inside a sheet with ~280px of usable content width) the original 170px trigger left too little room for the input+submit button.
  5. **`SocialBar.tsx`:** bump the Notifications button (line 62) and Messages button (line 73) from `h-10 w-10` to `h-11 w-11` (40px → 44px). Bump the avatar trigger's two `h-10 w-10` instances (lines 81, 82) the same way for consistency, since the file is already open for this change and it's the same primary-action pattern (opens the account menu).
- **Acceptance criteria:**
  - At 320/360/390/414/768px on `/en`, `/en/all-ads`, `/en/category/cars-and-vehicles`, `/en/search`, `/en/login`, `/en/chats`, and one listing-detail route: no element right-edge exceeds `innerWidth + 1`.
  - The mobile sheet trigger is reachable and opens at 320px; inside it, the search input is focusable and submits; the logged-out Login/Register/Sell links (or, logged in, every `SocialBar` menu item) are tappable.
  - At `lg:` (1024px) and above, the nav renders the original desktop row with no visible change versus a pre-change screenshot.
  - `SearchBar`'s scope button and label never truncate to an unreadable sliver at 320px (manually eyeball — "All Categories" or a selected category name should still read as text, not just an ellipsis).
  - Notifications, Messages, and avatar-trigger hit areas measure ≥44×44 CSS px.
- **Verification steps:**
  - `pnpm --filter web lint` and `pnpm --filter web build` (the latter is the type gate — this repo has no `check-types` script for `web`).
  - `git grep -n "hidden lg:\|lg:hidden\|Sheet" apps/web/components/web/NavBar.tsx apps/web/components/web/MobileNavSheet.tsx` to confirm the split landed.
  - `node tasks/mobile-verify.mjs --base http://localhost:3011 --widths 320,360,390,768 --routes /en,/en/all-ads,/en/category/cars-and-vehicles,/en/search,/en/login` (see §5's note on why this needs a _fresh_ build, not the existing `:3011` process) — the script already exists in this repo and exits 1 on overflow.
  - Optional: `chrome-devtools-axi open <url>` for a manual look at the sheet opening/closing; the CLI bridge showed "no active session" in this planning session and may not be available to the implementer either — don't make it a hard dependency.
- **Risk:** M (highest-traffic file in the app, logged-in/logged-out branching, first real use of `Sheet` outside the admin sidebar). **Effort:** M.

### W2 — Card & category grid responsiveness

- **Goal:** Replace every fixed/unresponsive grid-column or min-width rule that forces horizontal overflow below 640px, using the exact breakpoint ladder the repo's own `CategoryGrid.tsx` already proves out.
- **Findings addressed:** MR-002, MR-003, MR-010, MR-005 (grid-card heart slice).
- **Allowed files (exclusive to W2):**
  - `apps/web/components/all-ads/AllAdsCategories.tsx`
  - `apps/web/components/category-layouts/SubcategoryGrid.tsx`
  - `apps/web/components/ads/GridCardPost.tsx`
- **Implementation approach:**
  1. **`AllAdsCategories.tsx:23`:** change `grid grid-cols-6 text-md gap-2` to `grid grid-cols-3 sm:grid-cols-4 md:grid-cols-6 text-md gap-2` — a byte-for-byte copy of the ladder already shipped in `CategoryGrid.tsx:47` for the same 64px-circle tile shape.
  2. **`SubcategoryGrid.tsx:43-48`:** delete the inline `style={{ gridTemplateColumns: ... }}` (Tailwind cannot JIT a class from a runtime-interpolated `cols` value, which is exactly why this was inline in the first place) and replace it with a `className` driven by a small literal lookup table, since `cols` is only ever `5|6|7|8` (verified against every entry in `SUBCATEGORY_LAYOUT`, `category/[categorySlug]/page.tsx:23-36` — all 12 categories enumerated, no other value exists):
     ```
     const GRID_COLS_CLASS: Record<number, string> = {
       5: "grid-cols-3 sm:grid-cols-4 md:grid-cols-5",
       6: "grid-cols-3 sm:grid-cols-4 md:grid-cols-6",
       7: "grid-cols-3 sm:grid-cols-4 md:grid-cols-7",
       8: "grid-cols-3 sm:grid-cols-4 md:grid-cols-8",
     };
     ```
     and `className={`text-center leading-normal grid gap-2 ${GRID_COLS_CLASS[cols] ?? GRID_COLS_CLASS[6]}`}` (fallback to 6 keeps this defensive against a future `cols` value without crashing, and keeps `cols: number` — no need to narrow the prop type, avoiding a wider API change). Every one of the four literal strings must stay written out in full in the source (not built by template interpolation) so Tailwind's static class scanner can see them.
  3. **`GridCardPost.tsx:43`:** change `min-w-[260px]` to `sm:min-w-[260px]` (drop the unprefixed floor, keep it from `sm:`/640px up). Below `sm:`, the card falls back to the CSS grid default (`justify-self: stretch`), filling whatever 1fr track its parent grid gives it — this is what lets a 2-column mobile grid actually render two columns instead of forcing 536px+ of combined floor width. This single change fixes the overflow on every page that renders `GridCardPost` (home, all-ads, search, category, subcategory) without touching any of those four page/feed files, since none of them declare a competing width rule of their own.
  4. **`GridCardPost.tsx:150`:** bump the heart button from `h-9 w-9` to `h-11 w-11` (36px → 44px) — same file already open for the min-width fix.
- **Acceptance criteria:**
  - _(Re-measure only after W1 lands — see §5; the shell currently masks these.)_ At 320/360/390/768px on `/en/all-ads`, `/en/category/cars-and-vehicles`, `/en/search`: no `AllAdsCategories`/`SubcategoryGrid`/`GridCardPost` element's right edge exceeds `innerWidth + 1`.
  - At 320px, the category/subcategory circle grid renders 3 columns (not clipped, not overlapping) and the card grid renders 2 columns without forcing the page wider than 320px.
  - At ≥1024px, both grids render identically to today (`md:grid-cols-6`/`md:grid-cols-{5,6,7,8}` unchanged at that breakpoint; `sm:min-w-[260px]` still applies there exactly as the old unconditional `min-w-[260px]` did).
  - `GridCardPost`'s heart button measures ≥44×44 CSS px.
- **Verification steps:**
  - `pnpm --filter web lint` / `pnpm --filter web build`.
  - `git grep -n "gridTemplateColumns" apps/web/components/category-layouts/SubcategoryGrid.tsx` should return **no matches** after the fix (confirms the inline style is gone, not just supplemented).
  - `git grep -n "min-w-\[260px\]" apps/web/components/ads/GridCardPost.tsx` should show `sm:min-w-[260px]`, not a bare `min-w-[260px]`.
  - `node tasks/mobile-verify.mjs --base <fresh-build-url> --widths 320,360,390,768 --routes /en/all-ads,/en/category/cars-and-vehicles,/en/search` once W1's shell fix is also live in that same build (see §5 sequencing note).
- **Risk:** S (narrow, well-precedented Tailwind class changes; the riskiest single line is the `GRID_COLS_CLASS` fallback, mitigated by the exhaustive `{5,6,7,8}` check above). **Effort:** S.

### W4 — Post-form category picker: touch-reachable subcategory switch

- **Goal:** Make the mock `DynamicForm`'s category picker (`CategorySelecter` in `PostForm.tsx`) operable by tap, not just mouse hover — this is the load-bearing fallback for any admin-created subcategory with no seeded `field_schema` (see `CLAUDE.md`'s "A subcategory created through the admin UI still has no working post form" known gap), so a touch-only admin/staff user testing a brand-new subcategory is currently unable to change category here at all.
- **Findings addressed:** MR-008.
- **Allowed files (exclusive to W4):**
  - `apps/web/components/post/PostForm.tsx`
- **Implementation approach:**
  - `PostForm.tsx:59-68`: the left-pane category `<button>` has only `onMouseEnter={() => setActiveCategory(category)}` (line 61). Add `onClick={() => setActiveCategory(category)}` alongside it (do not remove the hover handler — keep the two-pane hover preview as a progressive enhancement for desktop/mouse users; `onClick` additionally covers touch, keyboard-triggered synthetic clicks, and mouse clicks that land without a preceding `mouseenter`, e.g. after a scroll).
- **Acceptance criteria:**
